# Sentinel AI Phase 8.5 — Scanner Module Frontend↔Backend Integration

## 1. Current Architecture (verified)

**Backend** — FastAPI + SQLAlchemy (MySQL `omkar` db), no global prefix, no auth on scan endpoints. Scan stack:
- `POST /scanner/run` (daemon thread) and `POST /scans/` (BackgroundTasks) — body `ScanRequest {website_id, engine}`; target auto-filled from the website URL. Returns scan immediately with `status: "Pending"`.
- `GET /scanner/engines` → installed engines (nmap/nuclei/sqlmap/nikto/zap/ssl). `GET /scanner/{id}` / `GET /scans/{id}` / `GET /scanner/{id}/report` (returns `{id, engine, status, target, findings, risk_score, report: parsed_output, error}`). `GET /scans/history/{website_id}` per-website history. **No global list, no delete.** `POST /scanner/{id}/cancel`.
- Statuses: `Pending → Running → Completed|Failed`, plus `Cancelled`. No progress %/websocket — poll status. Each engine returns a distinct `parsed_output` shape (sqlmap object-findings; nmap/nuclei/nikto/zap/ssl array-findings; ssl uses `title` not `name`). `risk_score` (0–100) computed backend-side.

**Frontend** — React 19 + Vite 8 + Tailwind v4 + React Router 7, plain JSX, no state lib (plain hooks). Route `/scanner` → `ScannerLayout` (7 tabs: overview, sqlmap, nmap, nikto, nuclei, owasp-zap, ssl-analyzer). Only Overview + SQLMapTab are real; other 5 are `ScannerEnginePlaceholder` "Coming Soon" cards. `Report.jsx`/`ReportComponents.jsx` exist but are SQLMap-only and have a crash bug (unimported `ShieldCheck`/`Clock`).

**Critical mismatch (broken today):** current `api.js` scanner functions target an outdated contract — `startSQLMapScan(target)` sends `{engine, target}` (backend needs `{website_id, engine}`); `getScanHistory()` calls `GET /scanner/history` which doesn't exist; `ScanRow` reads `scan.scanner`/`scan.created_at` (backend returns `engine`/`started_at`).

## 2. Approved Decisions
- **Backend:** add exactly 2 minimal additive endpoints: `GET /scans` (all scans, newest first) + `DELETE /scans/{scan_id}`. Nothing else on the backend.
- **Target UX:** searchable website selector (replaces free-text URL field).
- **UI architecture:** ONE generic EngineTab + a renderer registry. No six separate page implementations, no placeholders.
- **Engine version:** display **N/A / Unknown** — the backend does not expose versions, so the UI will NOT infer/derive versions from scan results or any other data. Version is rendered only if the backend ever provides it directly (e.g., a `version` field on `/scanner/engines`); today it shows "N/A".

## 3. Frontend Architecture — Generic Engine Framework

### Renderer registry (the extension point)
`frontend/src/components/scanner/engineResults.jsx` exports `ENGINE_RENDERERS` — a map of `engineId → small renderer component`:

```js
ENGINE_RENDERERS = {
  sqlmap:     SQLMapResults,   // waf/dbms/injectable/http_errors/warnings/databases/timeline
  nmap:       NmapResults,     // hosts, ports, services, versions, OS detection
  nuclei:     NucleiResults,   // templates executed, CVEs, severity, tags, template names
  nikto:      NiktoResults,    // server info, headers, misconfigurations, outdated software
  "owasp-zap": ZapResults,     // spider/active scan, alerts, risk breakdown
  "ssl-analyzer": SSLResults,  // certificate, issuer, expiration, TLS version, cipher, SANs, health
}
```

Each renderer receives the scan's `parsed_output` and renders that engine's specific fields using existing design primitives. **Adding a future scanner (OpenVAS, Trivy, Burp, Wazuh, Nessus…) = backend support (factory + VALID_ENGINES) + one `SCANNER_ENGINES` entry + one small renderer added to this map. No new page, no EngineTab changes.** A short comment in the registry documents this extension path.

### Single reusable tab
`frontend/src/components/scanner/EngineTab.jsx` — one component instantiated for all 6 engines, driven by the engine's config from `SCANNER_ENGINES` (id, name, description, icon/accent) + props:
- Intro header (engine icon tile + name + description)
- Target Configuration card: `TargetSelect` (shared searchable website dropdown) + Start Scan button + "scan in progress" busy badge
- Live Status card: current active scan for this engine — status pill, elapsed timer, risk score + findings once completed, error display on failure
- Latest Results panel: renders `ENGINE_RENDERERS[engineId](parsed_output)` from the most recent completed scan of this engine (inline report, no navigation required)
- History table (engine-filtered, columns: ID, Target, Status, Created, Duration, Risk Score, Findings, Action)

`ScannerLayout.jsx` renders every engine tab as `<EngineTab engine={engineConfig} ... />` via a loop over `SCANNER_ENGINES.filter(e => e.isEngine)` — no per-engine JSX. `SQLMapTab.jsx` and `ScannerEnginePlaceholder.jsx` deleted. `ScannerTabs.jsx` stays.

### Shared, engine-agnostic pieces (updated, not duplicated)
- `scannerApi.js` (new service module, `websiteApi.js` pattern): `mapScanToFrontend` (engine→display name, `started_at`→`created_at`), `startScan(websiteId, engine)`, `getAllScans()`, `getScanById`, `getScanReport`, `cancelScan`, `deleteScan`, `getScannerEngines`; imports `getWebsites()`.
- `shared.jsx`: add `PENDING` to `ACTIVE_STATUSES`/`statusColor`/`StatusPill`; extend `ScanRow` with Risk Score + Findings columns and Delete action.
- `constants.js`: all 6 engines → `Ready`; each engine entry carries `icon`/`accent` metadata for the generic tab (single source of truth).
- `OverviewTab.jsx`: stat tiles (Total, Queued, Running, Completed, Failed, Critical Findings), Installed Scanners panel (from `/scanner/engines` — name, type, Ready/Running/Offline state; version shows **N/A** since backend doesn't expose it), Recent Scans table, Recent Vulnerabilities (from completed scans' parsed_output), Active Queue, Last Scan, Launchpad.
- `Report.jsx`/`ReportComponents.jsx`: engine-aware via the same `ENGINE_RENDERERS` + generic summary/risk/severity-distribution/findings/recommendations/raw-output/parsed-JSON(dev) sections; fixes the missing-import crash.

## 7. Execution Flow (Run Scan → Results, no refresh)
1. Pick registered website in selector → `startScan(website.id, engine)` → `POST /scanner/run` `{website_id, engine}` → scan `Pending` row appears.
2. 3s poll (`getAllScans()`) → `Running` (spinner badge, elapsed timer, live status card).
3. `Completed`/`Failed` → poll refreshes row (Risk Score + Findings), Latest Results panel renders `parsed_output` inline via the engine's renderer.
4. View Report → `/scanner/report/:id` (engine-aware page). Delete → confirm → `DELETE /scans/{id}`. Cancel → `POST /scanner/{id}/cancel`.

## 8. Error Handling
Backend offline (fetch fail → banner + Retry, Overview "Offline"), no websites registered (empty state → link to Websites module), scan Failed (friendly error from `error` field), delete/cancel failures (toasts). No crashes, no fake/hardcoded data — every displayed value from backend.

## 9. Assumptions
- All six engines show `Ready` (backend supports all six; missing binaries surface as per-scan Failed with friendly errors).
- Engine versions always display **N/A** (backend doesn't expose them; nothing is inferred from scan results).
- `console.error` kept in catch blocks per existing convention (spec bans `console.log` only).
